# LoRa-Simulator 载荷编解码测试功能使用指南

## 功能概述

载荷编解码测试功能（test_payload_codec）是 LoRa-Simulator 中用于自动化测试设备载荷编解码脚本的功能模块。该功能能够：

- 从 Excel 文件中读取测试用例
- 自动执行载荷编码和解码测试
- 验证编解码结果的正确性
- 生成详细的测试报告

## 配置说明

### 配置文件结构

在 `lora-simulator.toml` 配置文件中的 `[lora-simulator.test_payload_codec]` 部分进行配置：

```toml
[lora-simulator.test_payload_codec]
# 是否开启测试功能
enable = false

# 测试用例文件路径（Excel格式）
test_case_file = "/path/to/编解码数据表.xlsx"

# 测试结果文件保存目录
test_result_dir = "/path/to/test/results/"

# 编解码脚本目录路径
test_codec_dir = "/path/to/codec-release-git"

# 测试设备配置（可配置多个设备）
[[lora-simulator.test_payload_codec.test_device_sheet]]
sheet = "WT101"        # Excel中的工作表名称
device = "wt101"       # 设备型号名称

[[lora-simulator.test_payload_codec.test_device_sheet]]
sheet = "WT201"
device = "wt201"
```

### 配置参数详解

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `enable` | bool | 是 | 是否启用载荷编解码测试功能 |
| `test_case_file` | string | 是 | Excel 测试用例文件的完整路径 |
| `test_result_dir` | string | 是 | 测试结果文件的保存目录 |
| `test_codec_dir` | string | 是 | 编解码脚本文件的根目录 |
| `test_device_sheet` | array | 是 | 测试设备配置数组 |
| `test_device_sheet.sheet` | string | 是 | Excel 文件中的工作表名称 |
| `test_device_sheet.device` | string | 是 | 设备型号标识（用于查找编解码脚本） |

## 目录结构要求

### 编解码脚本目录结构

编解码脚本必须按照以下目录结构组织：

```
test_codec_dir/
└── vendors/
    └── milesight-iot/
        ├── wt101/
        │   ├── wt101-decoder.js
        │   └── wt101-encoder.js
        ├── wt201/
        │   ├── wt201-decoder.js
        │   └── wt201-encoder.js
        └── [其他设备型号]/
            ├── [设备型号]-decoder.js
            └── [设备型号]-encoder.js
```

### Excel 测试用例文件格式

Excel 文件应包含以下列：
- 测试用例数据（JSON格式）
- 期望的编码结果（十六进制字符串）
- 期望的解码结果
- 其他测试相关信息

## 使用步骤

### 1. 准备测试环境

1. 确保编解码脚本文件已正确放置在指定目录
2. 准备包含测试用例的 Excel 文件
3. 创建测试结果保存目录

### 2. 配置测试参数

编辑 `lora-simulator.toml` 文件：

```toml
[lora-simulator.test_payload_codec]
enable = true
test_case_file = "/mnt/data/work_code/gateway/lora-simulator/cmd/lora-simulator/payload_en_decoder/编解码数据表.xlsx"
test_result_dir = "/mnt/data/work_code/gateway/lora-simulator/cmd/lora-simulator/payload_en_decoder/"
test_codec_dir = "/mnt/data/work_code/gateway/github/codec-release-git"

[[lora-simulator.test_payload_codec.test_device_sheet]]
sheet = "WT101"
device = "wt101"

[[lora-simulator.test_payload_codec.test_device_sheet]]
sheet = "WT201"
device = "wt201"
```

### 3. 执行测试

运行 LoRa-Simulator 时，测试功能会自动执行：

```bash
./lora-simulator
```

### 4. 查看测试结果

测试完成后，会在 `test_result_dir` 目录下生成以下文件：

- `{device}-success.json`：测试成功的用例
- `{device}-failed.json`：测试失败的用例

## 测试流程说明

1. **读取配置**：系统读取配置文件中的测试设备列表
2. **解析测试用例**：从 Excel 文件中解析对应工作表的测试数据
3. **加载编解码脚本**：读取设备对应的编码器和解码器 JavaScript 文件
4. **执行编码测试**：
   - 将 JSON 数据通过编码器转换为十六进制字符串
   - 与期望结果进行比较
5. **执行解码测试**：
   - 将十六进制字符串通过解码器转换为 JSON 数据
   - 与期望结果进行比较
6. **生成测试报告**：将测试结果分类保存到 JSON 文件

## 故障排除

### 常见问题及解决方案

1. **脚本文件找不到**
   - 检查 `test_codec_dir` 路径是否正确
   - 确认编解码脚本文件名格式：`{device}-decoder.js` 和 `{device}-encoder.js`

2. **Excel 文件解析失败**
   - 确认 `test_case_file` 路径正确
   - 检查 Excel 文件格式和工作表名称

3. **测试结果不匹配**
   - 检查编解码脚本的逻辑
   - 验证测试用例数据的正确性
   - 查看详细的错误信息

### 日志信息

测试过程中会输出详细的日志信息：

```
simulator: test payload codec
simulator: test payload codec sheet: WT101
simulator: test payload codec device: wt101
TestPayloadCodec: failed to read decode script: [错误信息]
TestPayloadCodec: failed to encode payload codec: [错误信息]
```

## 扩展配置

### 添加新设备测试

要为新设备添加测试，需要：

1. 在 Excel 文件中创建新的工作表
2. 在编解码脚本目录中添加设备脚本
3. 在配置文件中添加新的设备配置：

```toml
[[lora-simulator.test_payload_codec.test_device_sheet]]
sheet = "NEW_DEVICE_SHEET"
device = "new_device"
```

### 性能优化

测试过程中包含延时机制（每个测试用例间隔 3 秒），如需调整可修改源代码中的 `time.Sleep(3 * time.Second)` 参数。

## 注意事项

1. 确保所有路径使用绝对路径
2. 编解码脚本必须是有效的 JavaScript 代码
3. Excel 文件必须包含正确格式的测试数据
4. 测试过程中会消耗一定的 API 调用次数
5. 建议在测试环境中运行，避免影响生产数据
