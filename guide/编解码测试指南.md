# TestPayloadCodec 功能使用指南

## 功能概述

TestPayloadCodec 是一个用于测试 LoRa 设备载荷编解码功能的自动化测试工具。该工具能够：

- 自动解析 Excel 测试用例文件
- 对多个 LoRa 网关进行编解码测试
- 比较不同网关之间的测试结果差异
- 生成详细的测试报告和差异分析

## 主要特性

1. **多网关测试**：支持同时测试旧版和新版网关
2. **自动化测试**：从 Excel 文件读取测试用例，自动执行编解码测试
3. **结果比较**：自动比较不同网关的测试结果，找出差异
4. **详细报告**：生成 JSON 格式的测试报告和差异分析
5. **错误处理**：完善的错误处理和日志记录

## 配置说明

### 1. 配置文件位置

配置文件位于：`cmd/lora-simulator/config/lora-simulator.toml`

### 2. 配置参数

```toml
[lora-simulator.test_payload_codec]
# 是否开启测试
enable = true
# 旧版网关host
old_host = "192.168.40.147"
# 新版网关host
new_host = "192.168.40.148"
# API用户名
username = "your_username"
# API密码
password = "your_password"

# 测试用例文件路径
test_case_file = "/mnt/data/work_code/gateway/lora-simulator/codec.xlsx"

# 测试设备和对应的Excel工作表配置
[[lora-simulator.test_payload_codec.test_device_sheet]]
sheet = "WT201"
device = "WT201"
```

### 3. 配置参数说明

| 参数 | 说明 | 示例 |
|------|------|------|
| `enable` | 是否启用测试功能 | `true` / `false` |
| `old_host` | 旧版网关IP地址 | `192.168.40.147` |
| `new_host` | 新版网关IP地址 | `192.168.40.148` |
| `username` | API访问用户名 | `admin` |
| `password` | API访问密码 | `password123` |
| `test_case_file` | Excel测试用例文件路径 | `/path/to/codec.xlsx` |
| `sheet` | Excel工作表名称 | `WT201` |
| `device` | 对应的设备名称 | `WT201` |

## Excel 测试用例文件格式

### 1. 文件要求

- 文件格式：`.xlsx`
- 编码：UTF-8
- 工作表：每个设备对应一个工作表

### 2. 列结构

| 列名 | 说明 | 示例 |
|------|------|------|
| 中文含义 | 测试项描述 | `温度传感器` |
| 指令 | 16进制指令数据 | `0101` |
| 回复指令 | 编码后的数据 | `{"temp": 25}` |
| 编码格式 | 编码类型 | `decode` / `encode` |
| IPSO类型 | 设备类型 | `正常` |
| 代码 | 设备代码 | `WT201` |
| RAW | 原始数据 | `25.5` |
| 结果 | 期望结果 | `pass` |
| 错误信息 | 错误描述 | `解析失败` |
| tsl_config | TSL配置JSON | `{"id": "temp", "name": "温度"}` |

### 3. 示例数据

```
中文含义    指令    回复指令    编码格式    IPSO类型    代码    RAW    结果    错误信息    tsl_config
温度传感器  0101    {"temp":25}  decode    正常        WT201   25.5   pass   ""        {"id":"temp","name":"温度"}
湿度传感器  0202    {"hum":60}   decode    正常        WT201   60.0   pass   ""        {"id":"hum","name":"湿度"}
```

## 使用方法

### 1. 启动测试

```bash
# 进入项目目录
cd /mnt/data/work_code/gateway/lora-simulator

# 启动测试
./lora-simulator
```

### 2. 测试流程

1. **初始化连接**：连接到旧版网关
2. **执行测试**：读取Excel文件，执行编解码测试
3. **保存结果**：将旧版网关测试结果保存到 `old_host_test_result.json`
4. **切换网关**：连接到新版网关
5. **重复测试**：在新版网关上执行相同的测试
6. **保存结果**：将新版网关测试结果保存到 `new_host_test_result.json`
7. **比较结果**：比较两个网关的测试结果，生成差异报告

### 3. 输出文件

测试完成后会生成以下文件：

- `old_host_test_result.json`：旧版网关测试结果
- `new_host_test_result.json`：新版网关测试结果
- `test_result_diff.json`：测试结果差异分析

## 测试结果分析

### 1. 测试结果文件格式

```json
[
  {
    "device": "WT201",
    "test_result_item": [
      {
        "type": "decode",
        "data": "0101",
        "result": "{\"temp\": 25}",
        "error_msg": "",
        "success": true,
        "name": "温度传感器"
      }
    ]
  }
]
```

### 2. 差异分析文件格式

```json
{
  "total_diff_count": 5,
  "diff_items": [
    {
      "device": "WT201",
      "name": "温度传感器",
      "type": "decode",
      "data": "0101",
      "old_result": "{\"temp\": 25}",
      "new_result": "{\"temp\": 25.5}",
      "old_success": true,
      "new_success": true,
      "old_error_msg": "",
      "new_error_msg": "",
      "diff_type": "result_or_success_different"
    }
  ],
  "summary": {
    "old_host_file": "old_host_test_result.json",
    "new_host_file": "new_host_test_result.json",
    "compare_time": "2024-01-01 12:00:00"
  }
}
```

### 3. 差异类型说明

| 差异类型 | 说明 |
|----------|------|
| `device_not_exist_in_old` | 新网关有但旧网关没有的设备 |
| `device_not_exist_in_new` | 旧网关有但新网关没有的设备 |
| `test_item_not_exist_in_old` | 新网关有但旧网关没有的测试项 |
| `test_item_not_exist_in_new` | 旧网关有但新网关没有的测试项 |
| `result_or_success_different` | 结果或成功状态不同的测试项 |

## 常见问题

### 1. 连接失败

**问题**：无法连接到网关
**解决方案**：
- 检查网关IP地址是否正确
- 确认网络连接正常
- 验证API用户名和密码

### 2. Excel文件解析失败

**问题**：无法读取Excel文件
**解决方案**：
- 确认文件路径正确
- 检查文件格式是否为.xlsx
- 验证工作表名称是否正确

### 3. 测试项不匹配

**问题**：某些测试项在比较时找不到对应项
**解决方案**：
- 检查设备名称是否一致
- 确认测试项名称和类型是否匹配
- 验证Excel文件中的数据完整性

### 4. 编解码失败

**问题**：某些测试项编解码失败
**解决方案**：
- 检查16进制数据格式是否正确
- 验证编解码脚本是否存在
- 查看错误日志获取详细信息

## 日志查看

测试过程中的日志会输出到控制台，包括：

- 连接状态信息
- 测试进度
- 错误信息
- 比较结果统计

## 最佳实践

1. **测试前准备**：
   - 确保两个网关都正常运行
   - 验证Excel测试用例文件格式正确
   - 检查网络连接稳定性

2. **测试执行**：
   - 在非高峰期执行测试
   - 监控系统资源使用情况
   - 保持网络连接稳定

3. **结果分析**：
   - 重点关注差异类型为 `result_or_success_different` 的项
   - 分析失败原因并记录
   - 对比不同版本的网关性能

4. **报告维护**：
   - 定期清理旧的测试结果文件
   - 备份重要的测试报告
   - 建立测试结果历史记录
