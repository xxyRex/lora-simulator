# LoRa 设备模拟器 - 产品功能说明

## 产品概述

LoRa 设备模拟器是一款专业的 LoRaWAN 设备与网关仿真测试工具，用于 ChirpStack 应用服务器和网络服务器的功能验证与性能测试。该产品基于 Go 语言开发，支持大规模设备模拟、多种设备类型、以及高级协议测试功能。

**版本信息：** 1.0.0
**开发语言：** Go 1.23.0+
**协议支持：** LoRaWAN 1.0.x, MQTT, BACnet, Modbus
**适用场景：** ChirpStack 服务器测试、LoRaWAN 网络压力测试、设备集成验证

---

## 核心功能

### 1. LoRaWAN 设备模拟

#### 1.1 OTAA 入网激活
- **功能描述**：完整实现 LoRaWAN OTAA（Over-The-Air Activation）入网流程
- **支持特性**：
  - 自动生成 DevNonce 防止重放攻击
  - AppKey 加密 JoinRequest 消息
  - 自动解析 JoinAccept 并派生会话密钥（AppSKey, NwkSKey）
  - MIC（Message Integrity Code）完整性验证
- **设备类型**：支持 ClassA 和 ClassC 设备
- **并发能力**：单实例可模拟数百个设备同时入网

#### 1.2 数据上行/下行
- **上行数据传输**：
  - 周期性发送加密的上行数据帧
  - 可配置上行间隔（秒级精度）
  - 支持自定义 FPort 和负载数据
  - 自动递增帧计数器（fCntUp）
  - 负载加密与 MIC 校验

- **下行数据处理**：
  - 实时监听并处理网络服务器下行消息
  - 支持 ConfirmedDataDown 应答（ACK）
  - 帧计数器同步（fCntDown）
  - 下行数据解密与验证

#### 1.3 多设备类型支持
支持同时模拟多种设备类型，每种设备拥有独立的配置：

| 设备型号 | 设备类型 | 描述 | 支持的 Device Class |
|---------|---------|------|-------------------|
| **EM300-TH** | 温湿度传感器 | Temperature & Humidity Sensor | ClassA-OTAA |
| **VS330** | 占用传感器 | Bathroom Occupancy Sensor | ClassA-OTAA |
| **WT201** | 智能温控器 | Smart Radiator Thermostat | ClassC-OTAA |
| **UC100** | 控制器 | Controller | ClassC-OTAA |

**每种设备支持独立配置**：
- 独立的测试数据源
- 自定义上行间隔
- 专用的编解码器脚本
- 独立的 FPort 配置

### 2. LoRaWAN 网关模拟

#### 2.1 虚拟网关功能
- **网关数量**：每次模拟可创建 3-5 个虚拟网关（可配置）
- **MQTT 集成**：
  - 订阅下行主题：`gateway/{GatewayID}/tx`
  - 发布上行主题：`gateway/{GatewayID}/rx`
  - 支持 MQTT 用户名/密码认证
- **网关选择**：每个设备随机选择 3-5 个网关接收其信号
- **RXInfo 注入**：自动为上行帧添加接收信息（RSSI, SNR, 时间戳等）

#### 2.2 频率计划支持
支持全球主流 LoRaWAN 频率计划：

- **EU868** - 欧洲 868 MHz
- **CN470** - 中国 470 MHz
- **AS923-1/2/3/4** - 亚太 923 MHz 系列
- **AU915** - 澳大利亚 915 MHz
- **IN865** - 印度 865 MHz
- **RU864** - 俄罗斯 864 MHz
- **KR920** - 韩国 920 MHz

### 3. 高级测试功能

#### 3.1 Normal 模式（基础模拟）
- 标准 LoRaWAN 设备入网与数据传输
- 网关转发模拟
- Prometheus 指标监控
- 适用于基础功能验证和性能测试

#### 3.2 BACnet 协议测试
- **功能描述**：测试 ChirpStack 应用服务器的 BACnet 协议集成
- **支持操作**：
  - 获取可用 BACnet 对象列表
  - 根据测试数据过滤对象
  - 向 BACnet 服务器添加对象
  - 验证对象读写功能
- **适用场景**：楼宇自动化系统集成测试

#### 3.3 Modbus 协议测试
- **功能描述**：测试 ChirpStack 应用服务器的 Modbus 协议集成
- **支持操作**：
  - 创建 Modbus 服务器
  - 获取可用 Modbus 对象
  - 添加寄存器映射
  - 验证寄存器读写
- **适用场景**：工业控制系统集成测试

#### 3.4 FUOTA 固件升级测试
- **功能描述**：固件空中升级（Firmware Over-The-Air）功能测试
- **支持特性**：
  - 等待所有设备完成入网激活
  - 创建 FUOTA 任务并分配设备组
  - 分片传输（Fragmentation）支持
  - 组播设置（Multicast Setup）支持
- **适用场景**：大规模设备固件升级验证

---

### 4. 负载编解码测试

#### 4.1 JavaScript 编解码引擎
- **引擎**：基于 Goja JavaScript 引擎（ECMAScript 5.1+）
- **编码器函数**：`function Encode(fPort, obj) { ... }` → `{ bytes: [...] }`
- **解码器函数**：`function Decode(fPort, bytes) { ... }` → 对象
- **支持厂商**：Milesight IoT 等主流 LoRaWAN 设备厂商

#### 4.2 Excel 测试用例
- **功能描述**：从 Excel 文件批量导入编解码测试用例
- **测试流程**：
  1. 解析 Excel 测试表格
  2. 对每个设备类型加载编解码器
  3. 执行解码测试（Hex → JSON）
  4. 执行编码测试（JSON → Hex）
  5. 结果对比与报告生成
- **输出文件**：
  - 成功用例：`*-success.json`
  - 失败用例：`*-failed.json`
  - 对比报告：`test_result_diff.json`

### 5. 监控与指标

#### 5.1 Prometheus 集成
内置 Prometheus 指标收集器（默认端口 9000），支持以下指标：

| 指标名称 | 类型 | 描述 |
|---------|------|------|
| `device_join_request_total` | Counter | 设备发送的入网请求总数 |
| `device_join_accept_total` | Counter | 设备接收的入网成功总数 |
| `device_uplink_total` | Counter | 设备发送的上行数据总数 |
| `gateway_uplink_total` | Counter | 网关转发的上行数据总数 |
| `gateway_downlink_total` | Counter | 网关接收的下行数据总数 |

#### 5.2 日志记录
- **日志文件**：`simulator.log`
- **日志格式**：Logrus 结构化日志（带时间戳）
- **日志级别**：支持 Panic(0), Fatal(1), Error(2), Warning(3), Info(4), Debug(5)
- **内容包含**：设备状态变化、MQTT 消息、API 调用、错误信息等

### 6. 配置管理

#### 6.1 多配置文件系统
```
配置文件层次结构：
├── lora-simulator.toml           # 主配置文件（服务器连接、认证信息）
├── simulation-config.json        # 多设备类型模拟配置
├── devices.json                  # 设备类型定义与编解码器注册
├── devices_dynamic.json          # FUOTA 专用设备配置
└── base_devices_export.csv       # 设备模板导入（兼容模式）
```

#### 6.2 灵活的模拟控制
- **串行入网**：批量分批激活设备，避免网络服务器过载
- **并行入网**：所有设备同时发起入网请求（压力测试）
- **入网间隔**：可配置批次间隔（秒级）
- **模拟时长**：支持定时模拟或无限期运行
- **激活超时**：可配置设备激活等待时间

#### 6.3 TLS/HTTPS 支持
- **HTTP 模式**：`insecure = true`（适用于本地测试）
- **HTTPS 模式**：`insecure = false`（跳过证书验证，适用于自签名证书）

#### 7.1 自动资源管理
- **应用创建**：自动创建或查找应用（Application）

- 批量获取设备状态

## 技术特性

### 并发架构
- **Goroutine 并发模型**：每个设备运行两个独立 goroutine
  - `uplinkLoop()`：周期性上行数据发送
  - `downlinkLoop()`：异步下行消息处理
- **同步机制**：Context、WaitGroup、Channel、RWMutex
- **优雅关闭**：支持 SIGTERM 信号优雅退出

### 安全特性
- **加密算法**：AES128 加密（FRM Payload）
- **完整性校验**：所有消息携带 MIC
- **密钥派生**：遵循 LoRaWAN 标准的密钥派生算法
- **重放攻击防护**：DevNonce 和帧计数器机制

### 可扩展性
- **设备类型扩展**：添加 JavaScript 编解码器即可支持新设备
- **协议扩展**：模块化设计支持新协议集成
- **API 客户端生成**：基于 Swagger 自动生成 API 客户端代码

## 性能指标

### 模拟规模
- **设备数量**：单实例支持 500+ 设备并发模拟
- **网关数量**：单实例支持 100+ 虚拟网关
- **上行频率**：最小上行间隔 10 秒
- **激活速度**：批量激活模式下每秒可激活 0.5-1 个设备

### 资源消耗
- **内存占用**：100 设备约 200-300 MB
- **CPU 占用**：中等负载（取决于上行频率）
- **网络流量**：取决于设备数量和上行间隔
