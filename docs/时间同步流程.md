2. **发送强制同步请求阶段**

* 服务器向**待确认列表**中的所有设备发送 `ForceDeviceResyncReq`
* 使用  **FPort 202** （Clock Synchronization端口）
* 命令ID为  **0x03** （ForceDeviceResyncReq）
* 通过**单播**方式发送给每个设备

3. **等待设备请求时间阶段**

* 启动超时定时器（使用 `FirstWaitingTime`，根据设备类型不同）
* 监听设备的 **AppTimeReq** 上行消息（FPort 202，CID 0x00）
* 设备收到 `ForceDeviceResyncReq` 后会主动发送 `AppTimeReq` 询问服务器时间
* 响应到达或超时后进入处理阶段

4. **处理设备时间请求阶段**

 **收到 DeviceAppTimeReq（CID 0x02）** ：

* 解析消息，提取 `DeviceTime`（设备本地时间，uint32秒）
* 进入时间计算阶段

 **超时处理** ：

* 如果重试次数 < 最大重试次数：
  * 重试次数 +1
  * 返回步骤2（重新发送 ForceDeviceResyncReq）
* 如果重试次数 ≥ 最大重试次数：
  * 标记剩余未响应设备：`CLOCK_SYNC_STATUS_TIMEOUT`
  * 从待同步列表移除
  * 记录失败原因

5. **计算时间修正值阶段**

 **获取服务器时间（从上行数据包元数据）** ：

```Go
// AS从rxInfo中获取时间戳（Gateway在接收数据包时记录）
var serverTime uint32

// 优先级1: 使用rxInfo.Time（Gateway提供的时间戳）
for _, rxInfo := range uplinkData.RxInfo {
    if rxInfo.Time != "" {
        t, err := time.Parse(time.RFC3339Nano, rxInfo.Time)
        if err == nil {
            // 转换为GPS时间格式
            gpsTime := Time(t).TimeSinceGPSEpoch()
            serverTime = uint32((gpsTime / time.Second) % (1 << 32))
            break
        }
    }
}

// 优先级2: Fallback到系统时间
if serverTime == 0 {
    gpsTime := Time(time.Now()).TimeSinceGPSEpoch()
    serverTime = uint32((gpsTime / time.Second) % (1 << 32))
}
```

 **计算时间修正值** ：

```Go
// TimeCorrection = ServerTime - DeviceTime
// int32有符号数，可正可负
timeCorrection := int32(serverTime - deviceTime)
```

 **关键说明** ：

* AS无需关注Gateway是否有GPS硬件，AS只负责读取 `rxInfo.Time` 字段，`rxInfo.Time`由数据包转发层填充

6. **发送时间应答阶段**

 **发送 AppTimeAns（CID 0x01）** ：

```Go
// 构造AppTimeAns
payload := clocksync.AppTimeAnsPayload{
    TimeCorrection: timeCorrection,  // int32, 时间修正值（秒）
    TokenAns:       0,                // 基础实现不使用Token
}

// 发送到设备
SendDataDown(
    FPort:     202,  // Clock Sync FPort
    Data:      payload,
    Confirmed: false, // 不需要确认
)
```

 **标记设备状态** ：

* 立即标记：`CLOCK_SYNC_STATUS_COMPLETED`
* 从待同步列表移除
* 不等待设备确认（AppTimeAns不需要确认）

7. **完成判断阶段**

* **待确认列表为空** ：所有设备已处理（成功或失败），进入最终判断
* **判断是否有至少1台同步成功的设备** ：检查是否存在 `TS_STATUS_TIME_SYNC_DONE` 状态的设备
* **决策** ：
* 如果同步成功设备数量 = 0（全部失败）：中止FUOTA任务，记录失败原因
* 如果同步成功设备数量 ≥ 1（至少1台成功）：继续下一阶段（组播组创建）

8. **重试优化逻辑**

* 只向**仍在待确认列表**中的设备重发 `ForceDeviceResyncReq`
* 已确认成功或失败的设备不再重发
* 最多重试2次（总共3次尝试机会）
